The browser receives only signed-upload fields plus an opaque token; the final receipt is only an opaque ID and `Pending Review`. A reused token is accepted only for an identical idempotent retry while still valid. ## Anonymous-intake abuse and cost controls

The public upload-request route is throttled at 0.2 requests/second with burst 1; public create is throttled at 0.5 requests/second with burst 2 for a normal submission and immediate idempotent retry. The backend kill switch defaults off. A configurable atomic global UTC-day quota defaults to 20 upload-form grants, and the pending token and signed S3 form expire after five minutes. S3 enforces the 8-MB POST policy; raw uploads expire after one day. Neither route throttling nor the quota is a hard spending cap. The signed form can be replayed before expiry, and a malicious caller can exhaust the global quota, denying legitimate submissions. No raw IP is stored. The older protected `/v2` path retains its per-user 10-form daily cap; synthetic `/v1` has no per-user cap.

Before enabling anonymous intake, configure a low AWS Budget, monitor API Gateway 4xx/5xx/throttles, Lambda invocations, S3 requests/object growth and DynamoDB consumed requests, and assign an operator to disable the backend switch promptly if abuse occurs. Budget alerts can lag and do not stop charges. Review Cognito users and `varuna-responder` membership independently of anonymous intake. If legacy self-sign-up remains enabled, close it after that pilot and review existing accounts; the public real-road build must already use `VITE_PUBLIC_SIGNUP_ENABLED=false`.


The bucket blocks public access, encrypts objects, and accepts only a signed multipart POST with an S3-enforced `content-length-range` of 1 byte to 8 MB. Raw `uploads/` expire after one day; metadata-stripped private `review/` JPEGs expire after seven days. A responder-authorized detail request returns a 60-second presigned GET URL. Synthetic `/v1` and protected legacy `/v2` metadata include a server-derived owner subject; anonymous public `/v2` reports do **not** store reporter identity. Report metadata has a seven-day TTL (`expiresAtEpoch`), and expired records are hidden before DynamoDB's asynchronous deletion. S3 Lifecycle is also asynchronous; previously issued photo URLs can remain usable for up to their 60-second lifetime. Pending reports alter neither synthetic risk nor real-road condition. A reviewed `/v1` observation replays only in the historical **synthetic Scenario**; a responder-confirmed real-road outcome affects only its limited, current reviewed evidence. Neither is Live Delhi-wide flood intelligence or AI analysis.

The private bucket and retained report/alert tables use `Retain` on stack deletion to avoid accidental data loss. After a pilot, inspect and manually empty/delete retained resources only when authorized, after checking legal holds and records obligations. If an older report table contains items without `expiresAtEpoch`, inspect and remove or backfill them under an approved migration; DynamoDB cannot TTL-delete those items. The report tables do not request paid point-in-time recovery by default; the separate RoadAlerts table does request paid PITR, so check actual live settings and charges. Delete separately created Cognito users, group, app client, domain and pool only when no longer needed. S3/DynamoDB lifecycle and TTL are not immediate deletion guarantees.

The parser retrieves only `https://traffic.delhipolice.gov.in/en/news-alertadvisory/alerts` plus same-origin HTML details linked from its `<h2>` alert titles. It checks `robots.txt` before each bounded run, makes one listing request and at most ten new/changed detail requests sequentially, uses the same descriptive Varuna User-Agent and ten-second timeout, and refuses redirects, PDFs, social links, administrative paths and non-HTML responses. Per [RFC 9309 section 2.3.1](https://www.rfc-editor.org/rfc/rfc9309.html#section-2.3.1), a successfully fetched policy is obeyed; an HTTP 400–499 robots response except 429 is treated as unavailable and the **same** strict listing/detail allowlist may proceed with a non-fatal `robots_unavailable` source-health warning. A 429 defers further requests through its `Retry-After`; 5xx, network failure, malformed successful policy, uncertain rule evaluation or an applicable Disallow stops ingestion. Robots unavailability is not authorization and does not expand source scope. The adapter stores ETag/Last-Modified validators, source identifiers, text, dates when explicitly present, SHA-256 and parser version. A changed listing headline can trigger a conditional detail re-fetch and immutable revision; an unchanged listing is not a guarantee that an old detail has not changed. The adapter does **not** geocode or infer coordinates. Automatic imports begin Reported / Unverified, leave roads Unknown and cannot change `/v1` Scenario, resident reports or routing eligibility. Previous records survive source failure and carry their original timestamps; source-health state becomes stale/unavailable.
