# Scenario API and private photo reports

`template.yaml` defines API Gateway, the Scenario Lambda, a private encrypted S3 bucket for report photos, and a DynamoDB table for durable report metadata. It has no credentials. It does not configure Live weather, AI image analysis, Delhi-wide risk, or persistent closures. `Live` requests return 503. Packaging and building create no AWS resources.

The Lambda package contains only the Python backend modules needed by the handler, `data/fixture/scenario.json`, and `requirements.txt` for boto3 and Pillow. The staging script recreates `infra/.lambda-package/` from an explicit source allowlist; it refuses to replace that directory if unexpected files are present. Both staging and SAM build output are ignored by Git.

From the repository root, with Python 3.12 and AWS SAM CLI installed, build it with these exact commands:

```powershell
python infra/package_lambda.py
sam build --template-file infra/template.yaml
sam validate --template-file infra/template.yaml --lint --region ap-south-1
```

If SAM CLI is not on `PATH` but `uv` is available, use this exact alternative for the second command:

```powershell
uvx --python 3.12 --from aws-sam-cli==1.167.0 sam build --template-file infra/template.yaml
```

Inspect `.aws-sam/build/VarunaFixtureApi/` after building: it must not contain `frontend/`, `node_modules/`, tests, credentials, or `.git/`. Verify Pillow has Linux `.so` files rather than Windows `.pyd` files. If necessary, use `sam build --use-container --template-file infra/template.yaml` with Docker running. The handler and fixture paths are unchanged. Building does not deploy anything.

## Public sign-up abuse and cost controls

Public sign-up means anyone who confirms an account can request upload forms and send photos; authentication alone is **not** an upload quota. The signed S3 POST caps each upload at 8 MB and binds the key/type, but a form can be reused until its short expiry and repeated uploads can still incur S3 request/transfer charges. The API's default stage throttle is 2 requests/second with burst 10, and the upload-form route has a tighter 0.5 requests/second with burst 2. API Gateway throttling is best-effort, shared across callers, and **not** a per-user or spending ceiling; it may also slow legitimate users at peak. Raw upload objects expire after one day even when the user never finishes report creation. These controls limit individual objects and exposure time, not total spend.

Before opening public sign-up, configure an AWS Budget with low email alerts for this account/project and CloudWatch alarms or a staffed dashboard for Cognito `SignUpSuccesses`/`SignUpThrottles`, API `4xx`/`5xx`/throttles, Lambda invocations, S3 request/object growth and DynamoDB consumed requests. Budget alerts can lag and do **not** stop charges. Consider Cognito user-pool AWS WAF rate rules/CAPTCHA if sign-up abuse appears; WAF has its own cost and should be tested in Count mode first. Review service quotas, billing and any existing account-level protections. Do not promise a hard upload/spend cap: the current adapter has no per-user daily quota, so sustained abuse requires an operator to disable self-sign-up and/or the upload route promptly. Do not leave public uploads unattended.

After the event, in **Cognito user pool → Sign-up → Self-service sign-up → Edit**, disable self-registration and verify “Create an account” is no longer offered. Set `VITE_PUBLIC_SIGNUP_ENABLED=false` and rebuild/release the frontend so it says sign-in only; this browser flag never controls Cognito access. Existing users are **not** removed by the Cognito switch: review the Cognito Users list and `varuna-responder` group membership, disable suspicious or unneeded users (revoking sessions/tokens), and delete accounts only after the retention/records decision. Check the S3 bucket, DynamoDB table and billing for unexpected volume; then carry out the documented retained-resource cleanup. This post-event review is a manual operator task, not a SAM deployment side effect.

The bucket blocks public access, encrypts objects, and accepts only a signed multipart POST with an S3-enforced `content-length-range` of 1 byte to 8 MB. Raw `uploads/` expire after one day; metadata-stripped private `review/` JPEGs expire after seven days. A protected detail request returns a 60-second presigned GET URL. DynamoDB stores report metadata, server-derived owner subject, an idempotency fingerprint and a seven-day TTL (`expiresAtEpoch`). Expired records are hidden from list/detail and removed from risk **before** DynamoDB's asynchronous TTL deletion. S3 Lifecycle is also asynchronous; previously issued photo URLs can remain usable for up to their 60-second lifetime. Pending reports do not alter risk; acceptance requires a human visible-water decision and replays it at the historical fixture time in the **synthetic Scenario** only. This is not Live evidence, Delhi-wide risk, or AI analysis.

Both bucket and table use `Retain` on stack deletion to avoid accidental data loss. After a pilot, inspect and manually empty/delete the retained bucket and delete the retained table when authorized; confirm no legal hold or records obligation first. If upgrading a table that already contains uploads without `expiresAtEpoch`, the app hides those legacy records but DynamoDB cannot TTL-delete them; inspect and manually remove or backfill them under an approved migration. Delete the separately created Cognito users, group, app client, domain and pool only when no longer needed. The table does **not** request paid point-in-time recovery: this short, reproducible demo does not justify the additional cost. If updating a table where PITR was already enabled, inspect its actual post-update setting and charges instead of assuming template removal turns it off. Reassess PITR and backup/retention obligations before using real resident evidence or a longer-lived pilot. S3/DynamoDB lifecycle/TTL are not an immediate deletion guarantee.

The API URL, bucket name, and reports table name are stack outputs. To use a deployed API locally, set `VITE_USE_MOCKS=false`, `VITE_API_BASE_URL=<existing ApiBaseUrl output>`, `VITE_COGNITO_DOMAIN=https://<pool-domain>`, `VITE_COGNITO_CLIENT_ID=<public-app-client-id>`, and `VITE_COGNITO_REDIRECT_URI=<allowed-callback-url>` in ignored `frontend/.env.local`. Review origin, retention, budget, consent and privacy before deployment.
